1. COINS
    ==================================================

Add collectible coins throughout gameplay.

* Coins should spawn naturally during runs.
* Place coins at different heights and positions.
* Some coins should require jumping.
* Some should be placed along safer routes.
* Some can create risk/reward decisions.
* Never place coins inside unavoidable fork collisions.
* Never force the player to collect a coin.
* Survival must always be more important than collecting a coin.

COIN VISUALS:

* Create an original coin design matching the existing Fork Runner aesthetic.
* Add a subtle spinning/shimmering animation.
* Make coins immediately recognizable.
* Add a satisfying collection effect.
* Add a short original collection sound.

COIN COUNT:
Display the current run’s collected coins in the HUD.

Also maintain a persistent total coin balance using localStorage.

Example:

🪙 125

The persistent balance must survive:

* Game Over
* Retry
* Page refresh
* Closing and reopening the browser

If saved data is missing or corrupted:

* Coins = 0
* High score = 0

Never allow negative or invalid coin values.

2. POWER-UP SYSTEM

Create a proper reusable power-up architecture so additional power-ups can be added later without rewriting the game.

There should be FOUR power-ups:

A. 🧲 COIN MAGNET
B. 🛡️ SHIELD
C. ⏱️ SLOW MOTION
D. ⚡ INVINCIBILITY

Each power-up must have:

* Unique visual design
* Unique activation effect
* Unique sound
* Clear gameplay effect
* Controlled spawn frequency
* Optional configurable duration
* HUD indicator while active

Power-ups should be significantly rarer than coins.

Do NOT allow power-ups to spawn constantly.

==================================================
3. 🧲 COIN MAGNET

When collected:

* Automatically attract nearby coins toward the player.
* Coins should visibly move toward the player.
* The attraction should feel smooth rather than instant.
* The magnet should have a limited duration.
* Suggested duration: approximately 6–8 seconds.
* Make the duration configurable in the code.

Add:

* Magnetic visual effect around the player.
* Small particle/energy effect.
* HUD indicator showing the magnet is active.
* Countdown or progress indicator.

The magnet should only affect coins.

It must NOT attract power-ups or obstacles.

==================================================
4. 🛡️ SHIELD

When collected:

* Activate a protective shield around the player.
* The shield protects against ONE fork collision.
* When the player hits a fork:
    * Do NOT trigger Game Over.
    * Destroy/deactivate the shield.
    * Allow the player to continue running.
    * Play a satisfying impact effect.
    * Play a shield-break sound.
    * Give the player brief visual feedback.

The shield should then disappear.

IMPORTANT:
The shield is a ONE-HIT protection system.

Do not allow the shield to make the player permanently immune.

Show a small shield indicator in the HUD while active.

==================================================
5. ⏱️ SLOW MOTION

When collected:

* Temporarily slow down the obstacles and gameplay.
* Give the player additional reaction time.
* Suggested duration: approximately 4–5 seconds.
* Make the duration configurable.
* Slow the obstacle movement smoothly rather than instantly.
* Restore normal speed smoothly when the effect ends.

IMPORTANT:
Slow Motion should modify the effective gameplay speed without destroying the V3 difficulty progression.

Do not permanently reduce the game’s difficulty.

Add:

* Distinct visual effect.
* Subtle time-warp/particle effect.
* HUD indicator.
* Countdown/progress indicator.
* Activation and expiration sound.

==================================================
6. ⚡ INVINCIBILITY

Add a rare temporary invincibility power-up.

Suggested duration:
approximately 5 seconds.

Make the duration configurable.

While active:

* The player cannot be killed by fork collisions.
* Forks can touch/pass through the player without causing Game Over.
* The player remains fully controllable.
* Normal movement and jumping continue.

Visual effects:

* Strong but tasteful glow/aura.
* Particles or energy trail.
* Distinct character effect.
* Clear HUD indicator.

Display a countdown:

INVINCIBLE 5
INVINCIBLE 4
INVINCIBLE 3
INVINCIBLE 2
INVINCIBLE 1

During approximately the final second:

* Make the visual effect subtly flash.
* Clearly communicate that invincibility is about to expire.

When it reaches zero:

* Remove the effect.
* Restore normal collision behavior.
* Remove the HUD countdown.

Do not allow invincibility to stack indefinitely.

==================================================
7. POWER-UP SPAWNING & FAIRNESS

Power-up generation is extremely important.

Power-ups should be:

* Rare
* Valuable
* Strategically placed
* Collectible without creating unfair deaths

Never:

* Spawn a power-up directly inside a fork.
* Spawn a power-up where collecting it requires an impossible jump.
* Create a situation where the player must collect a power-up to survive.
* Spawn multiple powerful power-ups constantly.
* Create an unavoidable obstacle sequence around a power-up.

Power-up spawning should respect the existing V3 obstacle-generation and fairness system.

The player should always be able to ignore a power-up and safely continue the run.

==================================================

Use reasonable rarity and balancing.

Suggested hierarchy:

COMMON:
🪙 Coins

UNCOMMON:
🧲 Coin Magnet
🛡️ Shield

RARE:
⏱️ Slow Motion

VERY RARE:
⚡ Invincibility

Do not make these exact probabilities mandatory. Tune them based on actual gameplay testing.

The goal is:

“Wow, I got a power-up!”

rather than:

“There is another power-up every five seconds.”

==================================================
9. POWER-UP STACKING

Prevent power-ups from creating broken gameplay.

Decide intelligently how simultaneous effects should behave.

Examples:

* Magnet + Shield can coexist.
* Magnet + Invincibility can coexist.
* Shield + Invincibility can coexist.
* Slow Motion + Invincibility can coexist.

If the same power-up is collected while it is already active:

* Do NOT create unlimited stacking.
* Either refresh the duration or ignore the duplicate.
* Choose whichever produces the better gameplay experience.

Make the behavior consistent.
