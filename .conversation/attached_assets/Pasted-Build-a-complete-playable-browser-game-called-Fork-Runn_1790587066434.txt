Build a complete, playable browser game called Fork Runner.

Create a simple endless-runner game inspired by the gameplay simplicity of the Chrome Dinosaur game, but with completely original visuals and implementation.

CORE GAMEPLAY:

* The player character automatically runs from left to right.
* The player stays near the left side of the screen while obstacles move toward them from the right.
* On desktop, pressing Space or clicking/tapping the screen makes the player jump.
* On mobile, tapping anywhere on the game area makes the player jump.
* Spawn fork-shaped obstacles from the right side at random but fair intervals.
* The player must jump over the forks.
* If the player touches a fork, immediately stop the game.
* Show a clear Game Over screen with the final score and a prominent RETRY button.
* Pressing RETRY must instantly reset the game and start a new run.
* Add a score that increases continuously while the player survives.
* Gradually increase the obstacle movement speed as the score increases.
* Make the collision detection reliable and forgiving enough to feel fair.

DESIGN:

* Make it clean, modern, smooth and visually appealing.
* Do NOT copy Chrome Dinosaur artwork, sprites, branding or UI.
* Create original simple vector/CSS/canvas-style graphics for the character, ground and forks.
* Use a polished background with subtle depth/parallax if possible.
* Add smooth jumping and movement animations.
* Add a small score display at the top.
* Add a start state with a simple “TAP TO START” / “PRESS SPACE TO START” prompt.
* Game Over should feel polished rather than just displaying plain text.

RESPONSIVENESS:

* Make the game work properly on desktop, tablet and mobile.
* It must fit the entire browser viewport without unwanted scrolling.
* Make touch controls responsive on iPhone.
* Prevent accidental page scrolling when playing.

TECHNICAL:

* Keep the implementation lightweight and fast.
* Use HTML, CSS and JavaScript or the simplest appropriate frontend setup already available in this Replit project.
* Use requestAnimationFrame or an equivalent smooth game loop.
* Keep the game logic organized and maintainable.
* Do not add unnecessary backend/database/authentication because this game does not need them.
* Avoid external dependencies unless genuinely necessary.
* Make sure there are no console errors.
* Test the complete gameplay flow: start → jump → avoid forks → score → collision → Game Over → Retry → new game.

IMPORTANT:
Do not just create a mockup or static screen. Build the actual fully playable game and run/test it in Replit. If the project already contains files, inspect the existing structure first and modify it without unnecessarily breaking the project.
